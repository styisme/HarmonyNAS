# 开发环境约束说明 (DEVELOPMENT_ENV)

本文档说明本仓库（HarmonyNAS 鸿蒙原生版）的**实际开发条件**与**责任边界**。

它的作用是：**让外部能看清"我们做了什么、没条件做什么"**，而不是套用一套"有本地 IDE、有 CI、有真机"的标准模板。

> 不同仓库条件不同。本文件允许按实际情况**勾选**，不强迫所有项目都声称完成了全部流程。

---

## 一、开发环境（按实际勾选）

- [ ] 有本地 IDE / SDK，可本地编译
- [ ] 有本地 diff 工具，可逐行审阅
- [ ] 可跑 lint / 单元测试
- [ ] 走标准 PR 流程（fork → PR → review）
- [ ] **仅靠云端 CI 编译（无本地工具链）**
- [x] **仅靠移动端开发（纯 AI 生成与文本编辑，当前无实际编译环境）**
- [x] **走直推 master（无 PR 流程，个人作者主导的独立分支）**

> 未勾选的条目，代表**本仓库物理上无法执行**，不是"忽略了"。本项目作为纯 AI 驱动的重构产物，开发者在物理层面缺乏运行 DevEco Studio 编译 HAP 包的硬件/系统条件。

## 三、诚实声明

**以下情况必须如实标注，不得美化：**

**⚠️ 核心声明：**
> 「本仓库的代码未经任何编译与真机测试。所有代码均由 AI 直接生成，在物理层面没有经过 DevEco Studio 的语法检查，也没有在鸿蒙真机或模拟器上运行过。代码仅代表架构逻辑与设计思想，不代表功能可直接运行可用。使用前请自行评估风险，并承担编译排错的主要工作。」

**由于未经过编译环境，以下模块在代码逻辑上敏感且完全未验证：**

- 纯手写 TCP 协议栈（极易因鸿蒙严格类型推导报错）
- 鸿蒙原生长时任务（后台保活）的生命周期绑定
- 多设备自适应 UI 组件（`@State` 与 `@Link` 的状态流转）

## 五、我们承认这不完美

形式化的 PR 流程、逐行代码审阅、本地静态分析，这些在本仓库里**全部缺位**。

我们用「**极度的诚实披露 + 高危默认关 + 架构蓝图**」承担了**实质责任**，而不是假装做到了所有**形式责任**。

这是约束下的选择，不是对标准的否定。作为一个在极端限制下由 AI 生成的独立重构分支，它的历史使命是提供一种“零依赖的鸿蒙原生 NAS”的参考实现。

---

## 六、给其他极限约束开发者的建议

如果你也在极端约束下开发（无本地工具链 / 纯靠 AI 生成 / 无法编译），这套最小责任清单供参考：

1. **诚实披露 AI 参与度与测试状态**（不要美化比例，没编译就是没编译）
2. **高危功能默认关闭**（代码层面）
3. **敏感模块清单公开**（让外部能核对你写得有多疯）
4. **保持架构与文档清晰**（既然无法保证代码运行，就要保证逻辑严密）
5. **欢迎社区共建**（把编译报错排雷的工作交给有环境的极客）

**五件事做到了，你就已经承担了人类责任。** 形式上像不像别人，不重要。
